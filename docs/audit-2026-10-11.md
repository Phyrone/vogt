## Must fix

### 1. One bad folder locks the whole app

- **Where:** `sync_repositories` in `src-tauri/src/index.rs:477-486`; called from `src/routes/+layout.ts:15`.
- **Case:** A registered folder is not a git repository, or was moved, deleted, or sits on an unplugged drive. `ensure` → `watch` → `history::git_dirs` fails, `?` fails the whole command, the root `load` rejects, and every route shows an error. The bad entry cannot be removed from inside the app. "Add existing folder" (`src/routes/workspaces/[workspace]/+page.svelte:18-34`) accepts any folder, so one wrong pick is enough.
- **Change:** In the loop, log the failure with the repository id and continue with the next entry. The repository's own page already reports its error through `open_history`.
- **Also:** `open_history` (`src-tauri/src/history.rs:828`) calls `ensure` before it reads the refs, so a non-repository reaches the user as libgit2's raw message and never as "This folder is not a git repository." (`history.rs:835-838`). Map the error from `ensure` the same way.
- **Done when:** the test from task 11 passes with a broken path first in the list, and opening that broken repository's route shows the 422 page with the friendly message while every other route still works.

### 2. Old commits stay in the graph after amend or rebase

- **Where:** `note_heads` and `read_heads` in `src-tauri/src/index.rs:389-429`; `Refs::tips` and `Refs::heads` in `src-tauri/src/history.rs:57-76`; the call in `open_history` (`history.rs:839-843`) and in `sync` (`index.rs:211`).
- **Case:** HEAD is at commit `B`; opening the history saves `B` in the cache's `heads` list. `git commit --amend` makes `B'`. `B` is still a tip, so it stays in the view as a line flagged `merged` and named by its hash. After a rebase the whole old chain stays. The list is never pruned, and every HEAD move costs a second full layout (one for the ref, one for the newly noted head).
- **Why the list exists:** a linked worktree with a detached HEAD has a commit no branch reaches, and it must still be walked and drawn.
- **Change:** Read the HEAD of every worktree fresh inside `refs()` and put those in `Refs::heads`. `src-tauri/src/git.rs:26-59` already enumerates the worktrees (`main.worktrees()` → `find_worktree` → `Repository::open_from_worktree`); share that enumeration. Then delete `note_heads`, `read_heads`, both calls, and every use of the `heads` meta key.
- **Existing caches:** the stale `heads` key is harmless once nothing reads it. The fingerprint changes because the `worktree` lines change, so the next sync lays the view out again and the ghosts leave. Confirm this in the test.
- **Done when:** a Rust test walks a repository, replaces the tip of `main` with a sibling commit (same parent), walks again, and finds the old tip absent from `node`; a second test finds the detached HEAD commit of a linked worktree present; `grep -rn 'note_heads\|read_heads\|"heads"' src-tauri/src` prints nothing.

### 3. The history list crashes when a new line appears

- **Where:** `RepoSession.listen` in `src/lib/repo/session.svelte.ts:103-117`; the row template in `src/lib/components/History.svelte:273-297`; `line={lines[selected.line]}` in `src/routes/workspaces/[workspace]/repos/[repo]/history/+page.svelte:56`.
- **Case:** On `repo-changed` the handler sets `this.version` and only then starts `refresh()`. `History` watches `version` and fetches rows at once (two SQL reads), while `lines` arrives later with `open_history` (a git read plus about ten queries). A row on a line that is new in this version — a new branch with a commit, or a branch just merged and deleted, whose commits become `merged-<hash>` — gives `lines[commit.line] === undefined`, and `lineStyle(line)` and `line.name` throw.
- **Change, part one:** let `version` change only in `#apply`, together with `lines`. Keep the "already asked for this version" guard in a private field of its own.
- **Change, part two:** rows can still be newer than `lines` for a moment, so give a missing line one fallback in one place (`src/lib/repo/types.ts`), used by `History.svelte`, `LineBadge.svelte` and the page. `CommitGraph.svelte:23` shows the tolerant form: `lines[line]?.color ?? 'neutral'`.
- **Done when:** a `History.svelte.spec.ts` renders a source whose rows carry a line id that `lines` lacks, and the rows appear without an error; `AGENTS.md` (**Working with Svelte**) is satisfied for every touched component.

### 4. A graph edge gets a corner at row 18446744073709551615

- **Where:** `src-tauri/src/layout.rs:102`, `row.max(parent - (a - b))`.
- **Case:** `usize` arithmetic. When the lane distance `a - b` is larger than the parent's row, the subtraction underflows: a debug build panics with "attempt to subtract with overflow", a release build wraps. Reproduced with these stations (line, parent rows), trunk `0`, five lines:

  ```rust
  let rows = [
      station(1, &[7, 5]), // tip of a branch, a merge of line 2
      station(3, &[7]),    // tip of a second branch
      station(4, &[3]),    // tip of a third, made on the trunk commit right below
      station(0, &[4]),
      station(0, &[6]),
      station(2, &[7]),
      station(0, &[7]),
      station(0, &[]),
  ];
  ```

  Release output for the edge `2 -> 3`: `[[4, 2], [4, 18446744073709551615], [0, 3]]`.

- **Change:** `parent.saturating_sub(a - b)`. `src/lib/graph/layout.ts:113` is the same rule and already safe, because JS numbers go negative.
- **Done when:** a test in `layout.rs` lays out the stations above and the edge `2 -> 3` has the points `[[4, 2], [4, 2], [0, 3]]`.
- **Related:** a panic inside `materialize` ends the repository's worker task without `stopped` ever being notified, so `stop()` (`index.rs:197-201`) then waits forever. Task 6 covers that.

### 5. Everything shows "not pushed" when the remote is ahead

- **Where:** the tips of `walk` in `src-tauri/src/index.rs:263`; the `pushed` search in `src-tauri/src/history.rs:468-485`.
- **Case:** `git fetch` without a pull. `origin/main` now points at a commit that only the remote branch reaches. `walk` enqueues `refs.tips()` — local branches and HEADs — so that commit is not in the cache, `index.get(tip)` finds nothing, the search starts nowhere, and every commit is marked unpushed. The Push button shows the length of the whole line.
- **Change:** in `walk`, enqueue `refs.remote_tips` next to `refs.tips()`. Leave `Refs::tips()` as it is, so the view still holds only what local refs reach.
- **Order:** land task 8 first. After this change `indexed` stays above `laid` for such a repository, and task 8 removes the check that compares them.
- **Owner's question, not part of this task:** whether fetched commits that are not merged yet should be drawn in the graph.
- **Done when:** a Rust test creates `main` at `A` and `refs/remotes/origin/main` at a child `B`, walks, and finds `A` with `pushed = 1` in `node` and `B` absent from it.

### 6. Removing a repository fails on Windows and leaks everywhere

- **Where:** `watch` (`src-tauri/src/index.rs:137-170`), `stop` (`index.rs:197-201`), `forget_repo` (`index.rs:493-510`), `cache::remove` (`src-tauri/src/cache.rs:195-213`); `removeRepo` in `src/lib/registry/database.ts:45-49`; `remove` in `src/routes/workspaces/[workspace]/+page.svelte:36-39`.
- **Case, Windows:** at the delete, the Rust pool and the frontend's plugin connection both still hold the file. SQLite opens files on Windows without delete sharing, so `remove_file` fails. The registry row is already gone, `remove()` has no `catch`, the list is not refreshed, and the cache file is orphaned. Not run on Windows; read from the code.
- **Case, every system:** the watcher's callback owns an `Arc<Repo>` and the `Repo` owns the watcher. Nothing breaks the cycle, so each removed repository keeps a watcher and four SQLite connections until the app quits.
- **Change, Rust:** in `stop`, after the worker is gone, take the watcher out of its `Mutex` and `pool.close().await`. Make the worker notify `stopped` on every exit, a panic included (a drop guard does it), so `stop` cannot hang.
- **Change, frontend:** close the frontend's connection before `forget_repo` runs. The `open` map in `src/lib/db/repo.ts:43` is keyed by cache path, which the frontend only learns from `forget_repo`; key it by repository id so it can close first. Call `forget_repo` before deleting the registry row, so a failure leaves a repository the user can remove again, and show the failure in `remove()` the way `add()` does.
- **Done when:** the test from task 11 forgets a repository and finds its `.db`, `.db-wal` and `.db-shm` gone on all three CI systems; `database.spec.ts` shows the row still present when `forget_repo` rejects.

### 7. A new stash or a same-commit branch switch is not shown

- **Where:** `Refs::fingerprint` in `src-tauri/src/history.rs:79-97`; the early return in `walk`, `src-tauri/src/index.rs:248-251`.
- **Case:** `git stash`, or `git switch` to a branch that points at the same commit. Neither changes a line of the fingerprint, so `walk` returns before `report` and the frontend hears nothing. The sidebar keeps the old stash list and the old checked-out branch. The branch order that decides which line claims a commit depends on `head_branch` too, so the layout is stale as well.
- **Change:** add `head_branch` and the stashes, with their positions, to the fingerprint.
- **Cost:** a stash now triggers a full re-layout; the `shortcut:` note on `cache::save_view` covers that.
- **Known limit, leave it:** `git stash drop stash@{1}` only rewrites `logs/refs/stash`, which is not watched.
- **Done when:** a Rust test shows the fingerprint differs after `stash_save` and after `set_head` to a second branch on the same commit.

### 8. Quitting during a re-layout leaves the old graph

- **Where:** the end of `walk`, `src-tauri/src/index.rs:365-385`, and its early return, `index.rs:249`.
- **Case:** a ref change that brings no new commit — a tag added, a branch deleted. `walk` stores the new fingerprint, then starts `materialize`, which takes seconds on a large repository. The app quits in between. At the next start the fingerprint matches, `indexed == laid` still holds, and the walk returns early: the view stays stale until another ref moves.
- **Change:** store `complete` and the fingerprint after the last `materialize`. With that order the early return needs only `unchanged && progress.complete`; drop `indexed == laid`. The third condition of the final `if` (`laid != cache::progress(...).laid`) can never be true; drop it too.
- **Done when:** a Rust test walks, deletes a branch whose commit then leaves the view, walks again, and finds `laid` one lower with the new fingerprint stored; a further walk with unchanged refs calls `report` zero times even though `indexed != laid`.

### 12. Renovate merges every update by itself — owner decides

## Nice to have

### 15. Every commit is read from git twice during indexing

- **Where:** `walk`, `src-tauri/src/index.rs:310-318`.
- **Case:** each popped commit is read from git again only for its parents, which were stored in `commits.parents` when it was enqueued.
- **Change:** read the parents of the popped hashes from the cache in one query.
- **Done when:** the three existing `walk` tests pass and `read_facts` is called only for commits the cache does not hold.

### 16. The watcher wakes on every `.git/index` change

- **Where:** the callback in `watch`, `src-tauri/src/index.rs:140-145`.
- **Case:** an editor's `git status` rewrites `index` and `index.lock` every few seconds; each event starts a sync that reads and peels every ref.
- **Change:** a small `fn relevant(paths: &[PathBuf]) -> bool` that is false when every path is `index` or ends in `.lock`; the callback asks it. A ref update still arrives as the rename onto the final name.
- **Done when:** a unit test pins `relevant` for `index`, `index.lock`, `HEAD`, `packed-refs` and a path under `refs/heads/`.

### 17. A change listener can be left behind

- **Where:** `src/routes/workspaces/[workspace]/repos/[repo]/+layout.svelte:9-13`.
- **Case:** the session changes before `listen()` resolves. The cleanup runs while `stop` is still undefined, the listener stays, and the old session re-reads its repository on every change from then on.
- **Change:** a `cancelled` flag set in the cleanup; when the promise resolves after it, call `off()` at once.
- **Done when:** the effect holds no path on which a resolved `off` is dropped.

### 18. Two queries scan the whole view

- **Where:** `ahead` in `src-tauri/src/cache.rs:530-538`; the row query of `materialize_mask` in `src-tauri/src/history.rs:562-571`.
- **Case:** both filter `node` by `line`, which has no index, so they read every row of the view. `ahead` runs on every refresh: a few commits are counted by reading 500,000 rows.
- **Change:** an index on `(view_id, line)` in `src/lib/db/repo-schema.ts`, generated as a new migration.
- **Done when:** `EXPLAIN QUERY PLAN` for both queries names the new index, and `every_repo_migration_is_included` passes.
